# WhatsApp Gateway (OpenWA) — Deployment Guide

MOHD.HMS ENTERPRISE uses **OpenWA** (https://github.com/rmyndharis/OpenWA) as the
WhatsApp gateway/transport ONLY. MOHD.HMS remains the business system of record.

- **Pinned version**: v0.23.5, commit `bcd820d51b48701d051f659202dfdaa8b85f8373`
  (recorded in the clone at `PINNED_COMMIT.txt`). Verify API compatibility before
  upgrading (§47 of the WhatsApp spec).
- The gateway runs as an independent service on **port 2785** (API + Swagger at
  `/api/docs`). This directory is git-ignored — deploy by cloning the pinned
  commit on the target host (Docker/Compose on the home server, bare Node here).

## Local (sandbox) deployment — the one actually used in QA

```bash
git clone --depth 1 https://github.com/rmyndharis/OpenWA.git openwa
cd openwa
git fetch --depth 1 origin bcd820d51b48701d051f659202dfdaa8b85f8373  # pin
npm ci                                     # PUPPETEER_SKIP_DOWNLOAD=true is fine (Baileys engine)
npm run build                              # nest build → dist/
mkdir -p data
# .env.runtime (NOT committed):
#   PORT=2785
#   NODE_ENV=development
#   ENGINE_TYPE=baileys
#   API_MASTER_KEY=<openssl rand -hex 24>
#   MAIN_DATABASE_NAME=./data/main.sqlite
#   DATABASE_TYPE=sqlite                    # production: postgres (see below)
#   DATABASE_NAME=./data/openwa.sqlite
#   BAILEYS_AUTH_DIR=./data/baileys
#   SESSION_DATA_PATH=./data/sessions
#   RESOLVE_LID_TO_PHONE=true               # §42: senderPhone on message.received
#   SSRF_ALLOWED_HOSTS=127.0.0.1,localhost  # allow the loopback webhook target
node dist/main.js
```

## Production notes (home server)

- **Database**: OpenWA's auth/audit DB is always SQLite (`MAIN_DATABASE_NAME`).
  The DATA database supports PostgreSQL: `DATABASE_TYPE=postgres` +
  `DATABASE_HOST/PORT/USERNAME/PASSWORD/NAME` + `POSTGRES_SCHEMA=openwa`
  (isolated schema in the EXISTING PostgreSQL server — no second server).
- **Storage**: keep the gateway's own session storage; business media is stored
  in MOHD.HMS MinIO (the app pulls from the gateway media endpoint once and
  persists to MinIO — OpenWA storage is transient).
- **Exposure**: OpenWA stays on the private network (never public). Webhooks:
  Internet → Cloudflare/Nginx → MOHD.HMS → loopback OpenWA.
- **Secrets**: `API_MASTER_KEY` is stored AES-256-GCM-encrypted inside MOHD.HMS
  (Settings → WhatsApp → Configuration). The webhook signing secret is
  generated by the operator, handed to OpenWA per webhook, and never leaves the
  two servers. No secrets in Git.
- **Pairing**: session `mohd-hms-production` is created via Settings → WhatsApp
  → Connect; then either scan the QR (Settings → WhatsApp → Show QR) or use the
  pairing-code dialog (POST /api/sessions/{id}/pairing-code).

## MOHD.HMS integration surfaces

- `src/lib/hms/whatsapp/*` — the ONE WhatsAppService (client, config, templates,
  automations, inbound router, worker, health). No module talks to OpenWA
  directly.
- `src/app/api/v1/whatsapp/*` — admin APIs (RBAC-gated) + the signed public
  webhook at `/api/v1/whatsapp/openwa/webhook` (X-OpenWA-Signature HMAC-SHA256,
  idempotent by `X-OpenWA-Idempotency-Key`).
- Settings → WhatsApp (admin administration) and the WhatsApp Inbox module
  (`/whatsapp`) for staff conversations.
- End-to-end QA: `bun scripts/whatsapp-qa.ts`.
